AgentOA 用户使用说明

面向 10–200 人内部团队的模块化办公系统：组织人事 · 流程审批 · 考勤打卡 · 报销财务 · 公告通知 · 知识库 · 日程会议任务 · 报表看板

适用版本：v1.0 功能范围（P0 + P1）｜文档版本 v1.1（新增云端服务器部署教程）｜更新日期 2026-10-05

PC 管理端（Vue 3 + Element Plus） 移动端 H5 / 微信小程序 单组织 · 权限分级 · 全程留痕

1. 产品概述

AgentOA 是一套可自部署的企业协同办公平台。核心能力覆盖「人事生命周期 → 审批流转 → 考勤/报销业务闭环 → 通知触达 → 知识沉淀 → 协同日程任务 → 数据看板」全链路，所有审批操作幂等防重、越权自动拦截、关键动作写入审计历史。

组织人事

部门/岗位/花名册、入职·转正·离职、调岗调薪、合同管理、Excel 导入导出、员工自助档案

流程审批

请假、加班、补卡、报销、入职/转正/离职等固定模板；同意/拒绝/转办/退回/加签/催办/抄送/委托

考勤打卡

上下班打卡与外勤打卡、补卡、假期额度账本与批次、排班、考勤统计与月报导出

报销财务

报销单、发票防重复占用、费用类型、预算控制、付款登记与财务报表

通知公告

公告发布/撤回、消息中心、模板消息、定时推送、通知偏好、失败重投

知识库

知识空间与成员角色、Markdown 文档、草稿/版本/回滚、文件柜、搜索、回收站、目录 ACL

日程会议任务

日程与可见范围、会议室预约/签到、重复日程、我的任务看板与协作

报表工作台

工作台聚合、人事/考勤/财务/流程看板、指标口径说明、报表导出任务

阅读对象本文档面向最终用户（员工/主管/HR/财务/出纳/总监）与系统管理员。开发与验收口径见仓库 docs/ 目录的 01–20 号设计文档。

2. 部署与启动

2.1 环境要求

项目要求
运行环境Docker Engine + Compose v2（Windows 需 Docker Desktop + Linux 容器）
构建环境JDK 17+、Maven 3.6+、Node.js ≥ 20.19（推荐 24.x）
浏览器Edge / Chrome / Firefox 近两年版本（推荐 Edge）
移动端手机浏览器（H5）或微信（小程序，需微信开发者工具上传）

2.2 一键启动（本地/内网）

# 在仓库根目录执行（首次启动建议带 -Build 重新构建镜像）
./scripts/start-local.ps1 -Build

# PowerShell 执行策略受限时：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1 -Build

启动脚本会自动：初始化密钥（scripts/init-secrets.ps1）→ 构建后端/前端/H5 镜像 → 启动 Compose 全栈并等待健康检查（最长 240 秒）。

服务地址说明
Web 门户（用户入口）http://localhost:18080PC 管理端静态站点（Nginx）
移动端 H5http://localhost:18082移动端 H5 静态站点（Nginx）
后端 APIhttp://localhost:18081Spring Boot（仅供联调/排障直连）
MySQL127.0.0.1:13306业务数据库 agentoa
Redis127.0.0.1:16379会话与缓存
S3 对象存储127.0.0.1:19000私有文件桶（SeaweedFS）
端口约定默认全部端口仅绑定本机地址（127.0.0.1），适合本地/内网验证。对外服务前请先完成 HTTPS/WSS、密钥管理与防火墙配置（云端服务器部署完整教程见 §15）。

2.3 日常命令

# 仅重启（不重新构建）
./scripts/start-local.ps1

# 手动构建
./scripts/build-backend.ps1
./scripts/build-frontend.ps1 -Install
./scripts/build-h5.ps1 -Install

# 停止（保留数据卷）
docker compose -f deploy/compose.yml down

# 查看日志
docker compose -f deploy/compose.yml logs -f backend web

2.4 升级与数据库迁移

数据库结构由 Flyway 版本化迁移管理（V1–V22），升级时按版本顺序自动执行，禁止修改已执行的迁移文件。迁移由独立账号 agentoa_migrate 执行（仅 DDL 权限），业务账号仅有增删改查权限。

3. 登录与账号安全

3.1 登录

  1. 浏览器打开 http://localhost:18080（云端部署为 https://你的域名），进入登录页。
  2. 输入管理员账号 admin（当前账号以 deploy/secrets/admin-current-username 为准）。
  3. 本地开发环境默认密码为 123456（当前密码同步记录在 deploy/secrets/admin-current-password）。生产部署必须立即修改默认密码：全新初始化的环境首次密码取自 deploy/secrets/bootstrap-password。
  4. 验证码：默认开启（算术验证码）。本地栈已在 deploy/.env 设 CAPTCHA_ENABLED=false 便于接口直连调试；接口直连登录时验证码字段传 captchaCode/captchaUuid（来自 GET /auth/code）。
  5. 若账号被标记强制改密，登录后会提示设置新密码（12–72 UTF-8 字节），改密后需重新登录。
账号安全规则本地默认凭据 admin/123456 仅限本机/内网开发验证，切勿用于生产；生产请使用强密码并开启验证码。忘记密码请联系管理员在「系统管理 → 用户管理」中重置。连续错误会触发登录限流。会话有效期 2 小时、30 分钟无操作过期；被停用的账号会立即失效其全部会话。

3.2 会话与多端

  • PC 与移动端使用同一套账号体系与会话令牌（不透明 Bearer，仅存内存）。
  • 在「个人中心 → 在线设备」可查看并下线其他设备。
  • 右上角铃铛为消息中心入口；头像菜单包含个人中心、修改密码、退出登录。

4. 角色与权限

系统采用「角色 → 菜单/按钮权限 + 数据范围」的授权模型。给用户分配角色后即时生效（重新登录后菜单刷新）。

角色角色标识典型使用者主要权限
超级管理员superadmin系统管理员全部菜单与系统管理（用户/角色/菜单/字典/日志/监控）
人力资源hrHR / 人事专员组织与花名册全量维护、入职转正离职、异动调薪、合同、公告发布、模板与定时推送、考勤维护、全模块报表
部门经理dept_manager部门负责人/直属主管本部门数据范围内的审批、考勤查看、报表看板、任务与日程
普通员工employee全员自助档案、发起申请、我的待办、打卡、余额查询、公告与消息、知识库参与、任务与日程自助
财务finance财务人员发票/费用类型/预算管理、报销审核视角、付款、财务报表与导出
出纳cashier出纳付款登记、待付款清单、财务报表只读
总监director高管审批与全模块报表看板（只读为主）
数据权限除按钮权限外，列表/详情/导出/文件下载均做对象级校验：私有数据越权返回 404、功能越权返回 403。例如私有日程、他人草稿、部门外花名册明细对无权用户不可见。

4.1 如何创建用户并授权（管理员）

  1. 「系统管理 → 用户管理 → 新增」填写账号/姓名/部门，初始密码由系统生成后强制首登修改。
  2. 在用户行点「更多 → 分配角色」勾选所需角色（可多角色叠加）。
  3. 如需按部门授权，「系统管理 → 角色管理」编辑角色的数据范围（本部门/全部/自定义）。
  4. 员工入职建档请优先走「人事 → 花名册 → 入职」，可同时开通系统账号。

5. 工作台首页

登录后进入工作台（/index），聚合展示与你相关的待办信息：

  • 我的待办：待审批任务，点击直达审批详情；
  • 我发起的：申请进度与当前节点；
  • 考勤状态：今日打卡情况；
  • 假期余额：各类假种剩余分钟/天数；
  • 今日日程：今日会议与日程安排；
  • 公告：最新公告速览。

左侧菜单按角色动态下发；顶部可切换语言、调整布局、进入个人中心。

6. 组织人事（HR）

6.1 组织与岗位

  • 部门管理：树形组织维护，支持新增/编辑/启停用/删除；部门与岗位名称在组织内唯一。
  • 岗位管理：岗位 CRUD，被员工引用的岗位不可删除。

6.2 花名册与员工生命周期

操作入口说明
建档/入职花名册 → 入职填写档案与岗位信息，可同时创建系统账号（账号一经关联不可换绑）
转正员工详情 → 转正状态 试用期 → 正式；也可走「转正申请」流程由审批驱动
离职员工详情 → 离职状态 离职中 → 已离职；生效后账号冻结、会话立即失效
状态修正员工详情 → 状态仅允许修正初始状态；在职生命周期由审批驱动
变动历史员工详情 → 变动记录岗位/部门/状态/薪资变动全程留痕（含操作人与时间）
导入/导出花名册 → 导入 / 导出Excel 导入带校验预览与报错行提示；导出按筛选条件

6.3 调岗调薪 / 合同 / 经历（P1）

  • 异动管理：调岗、调薪申请（携带 Idempotency-Key 幂等，重复提交不重复生效）；到期异动可一键执行。
  • 薪资保密：薪资字段 AES-256-GCM 加密存储，仅具备「薪资敏感」权限（hr:change:sensitive）者可见明文。
  • 合同管理：合同 CRUD、续签提醒（「即将到期合同」列表）。
  • 教育/工作经历：HR 可维护任意员工；员工本人可在「自助档案」维护自己的经历。
  • 员工自助：「个人中心 / 自助档案」查看与更新本人可维护字段。
提示删除部门/岗位前请先确认无员工引用；员工身份证/手机号等敏感字段对普通角色脱敏展示。

7. 流程审批

7.1 发起申请

入口：流程审批 → 我发起的 → 发起申请（移动端见 §14）。选择流程模板后按表单填写并提交，系统生成申请单草稿 → 提交后进入审批流转。

模板业务单关键校验
请假申请请假单假种/时长与假期额度联动，超额直接拒绝提交
加班申请加班单加班时长与类型；审批通过后计入加班台账
补卡申请补卡单补卡窗口限制；通过后补写打卡记录（一次生效）
报销申请报销单明细金额、发票占用、预算校验；明细超发票面额拒绝
入职 / 转正 / 离职申请生命周期申请单审批通过后驱动 HR 状态流转（转正 PROBATION→ACTIVE、离职 LEAVE_PENDING→LEFT）
会签 / 或签（示例模板）通用表单会签需全员通过；或签任一通过即通过

7.2 处理待办

  • 待办：列表显示标题/模板/当前节点；进入详情可查看表单、流转历史、流程图。
  • 同意 / 拒绝：填写意见后提交；拒绝需填原因。
  • 转办：将当前任务转交他人办理。
  • 退回：退回指定历史节点重新办理。
  • 加签：前加签（当前人之前插入办理人）/ 后加签（当前人之后追加）。
  • 催办：向当前办理人发送催办通知（重复催办去重）。
  • 抄送：将办理中的实例抄送给他人知会。

7.3 我发起的 / 已办 / 抄送

  • 我发起的：可撤销审批中的实例（撤销后业务单同步撤回并释放占用）。
  • 已办：历史办理记录，可追溯操作人、意见与时间。
  • 抄送：他人抄送给我的实例列表。

7.4 管理与监控（授权角色）

  • 流程定义：查看模板与版本（DRAFT/PUBLISHED/RETIRED）、表单 schema、发布新版本；已发布版本不可修改，历史实例不受影响。
  • 流程监控：实例挂起 / 恢复 / 终止（终止会把业务单置为合理终态并通知）。
  • 委托管理：设置委托人、有效期与范围；委托期间待办自动转给受托人。
  • 超时扫描：标记发起超过 24 小时仍在途的实例（超时标识 + 每实例一次去重通知）。
并发与幂等重复点击提交不会生成两单（同幂等键重放返回首次结果，同键不同请求返回 409）；版本冲突或状态冲突会返回 409 并提示刷新后重试，不会造成数据错乱。

8. 考勤打卡

8.1 打卡

  • 上下班打卡：「考勤 → 打卡」一键打卡，自动识别上午/下午班次；重复打卡返回窗口错误提示。
  • 外勤打卡：需同时提供 GPS 定位 + 现场照片（先上传照片再打卡）；适用于出差/外勤场景。
  • 补卡：漏打卡通过「补卡申请」走审批，通过后补写记录（一次生效，重复不叠加）。
  • 我的记录：按日查看打卡明细、出勤状态（正常/迟到/早退/缺勤/请假）、异常原因。

8.2 假期与额度

  • 额度账本：八类假种按分钟记账（480 分钟/天折算），发假/冻结/结算/释放/调整全程流水可查。
  • 假期批次（P1）：HR 发假支持有效期批次，按「先到期先扣」（FIFO）核销；过期额度自动作废（含定时扫描与手动扫描按钮）。
  • 余额查询：员工自助查看本人余额与台账；HR/主管可查本部门。

8.3 排班与规则维护（HR/管理员）

  • 班次管理：固定班 / 弹性班 / 跨夜班；跨夜班自动按日切分计算。
  • 考勤组：按部门/人员分组，绑定班次与日历。
  • 排班（P1）：按人按日指定班次（一天一班），可批量覆盖同日排班。
  • 考勤日历/节假日：维护工作日与法定节假日，节假日打卡不计迟到早退。

8.4 统计与导出

「考勤 → 报表」支持日统计、月统计与 Excel 导出（HR/主管权限）。日终自动结算出勤/请假/加班/异常，原始打卡记录全部保留可追溯。

9. 报销财务

9.1 员工：报销申请

  1. 「流程审批 → 发起申请 → 报销申请」（或移动端）填写明细：金额、费用类型、可选发票与说明。
  2. 提交前系统校验：明细金额、发票可用额度、预算余额；超额/超预算直接提示并拒绝提交。
  3. 提交后进入审批；审批通过进入「待付款」。

9.2 财务：发票与费用类型

  • 发票管理：登记发票（号码/代码唯一 + 规范化指纹去重），上传发票图片；同一发票重复登记返回 409。
  • 发票占用：报销提交时自动占用额度，拒绝/撤销自动释放；一票可拆分到多单，累计不得超面额。
  • 费用类型：维护报销费用分类（被引用不可删除）。
  • 预算管理（P1）：部门/项目预算与占用流水，提交/通过/转办/拒绝联动预算占用与释放，预算不足返回 409。

9.3 出纳：付款登记

  • 「财务 → 付款管理 → 待付款」查看已通过未付款的报销单。
  • 登记付款：金额、方式、流水号、备注；支持分次付款（多次付款累计不超过应付金额），每次登记需携带幂等键防重复。
  • 付款完成后报销单状态自动推进为「已付款」，付款记录不可重复登记（重复返回 409）。

9.4 报表

「财务 → 财务报表」提供费用类型分布、月度费用趋势（按发生日期区间、状态口径统计），支持 Excel 导出。口径详见报表模块的「指标口径」说明。

10. 通知公告

10.1 公告

  • 起草（HR）：标题、正文、公告类型、密级、受众范围（全员 / 部门 / 角色 / 指定人），可定时发布与失效时间。
  • 发布：发布瞬间固化内容与受众快照；发布后正文不可修改。
  • 撤回：撤回后受众不可见，本人/发布人可见并留痕。
  • 已读统计：按受众快照统计已读/未读名单（分母为快照人数），发布人/管理者可见。
  • 阅读：全员可浏览公告并自动标记已读（幂等，重复不重复计数）。

10.2 消息中心

  • 分类：待办 / 公告 / 提及 / 系统，支持未读筛选、全部已读、单条删除（软删除，保留审计）。
  • 待办消息可跳转到对应业务（审批、任务等）。
  • 实时提醒通过 WebSocket 推送；断线后自动补拉，不会丢消息。
  • 通知偏好：在消息中心设置各类消息是否提醒。

10.3 模板消息与定时推送（HR）

  • 模板管理：内置「入职欢迎、生日祝福、考勤异常提醒」模板；模板使用 {变量} 占位符，发送时变量缺失会提示（不执行表达式，安全）。
  • 模板发送：选择受众即时发送。
  • 定时推送：创建推送计划（类型/周期/受众/模板或公告），支持暂停/恢复、执行历史、手动触发一次。
  • 失败的推送会记录执行结果并可由管理员在消息事件中重投。

10.4 管理员：投递事件

「消息中心 → 投递事件」（管理员/授权角色）：查询失败事件、手动重投（有重投次数与时间审计）；失败 5 次自动转 FAILED 待人工处理。

11. 知识库

11.1 空间与成员

  • 空间：按部门/主题建立知识空间（类型：公司/部门/项目/个人）。
  • 成员角色：OWNER（拥有者）/ EDITOR（可编辑）/ COMMENTER（可评论）/ VIEWER（只读）；OWNER 不可被移除、降级。

11.2 文档

  • Markdown 编辑：所见即所得预览、目录树（支持多级子目录）、拖动归类。
  • 草稿与发布：编辑自动存个人草稿（30 天）；发布产生新版本；状态：草稿 / 已发布 / 已归档。
  • 版本与回滚：版本历史只追加不可改；对比差异；回滚生成新版本；并发编辑冲突返回 409（提示刷新重试）。
  • 目录 ACL（P1）：对目录/文档单独授权（用户/主体级），可设置「仅目录 ACL 生效」的强覆盖模式。
  • 回收站：删除进回收站，30 天内可恢复；到期清理。
  • 搜索：按标题与正文全文匹配，结果高亮，严格按空间权限过滤（无权文档不可见也不可搜到）。

11.3 文件柜与互动

  • 文件柜：上传附件（≤20 MiB，扩展名/魔数/MIME 三重校验），预览（图片/PDF/文本）、下载、删除、回收站恢复；下载有审计与时间限制。
  • 评论 / 点赞 / 收藏（P1）：COMMENTER 及以上可评论；收藏夹页面集中查看。
  • 个人收藏：收藏文档快捷入口。
权限要点知识库默认拒绝：未被授权的空间/文档，即使知道链接也返回 404/403。分享文档请通过成员管理或目录 ACL 显式授权。

15. 云端服务器部署教程

本章面向运维/实施人员，讲解把 AgentOA 部署到云服务器（阿里云 ECS、腾讯云 CVM、AWS EC2 等）并以 HTTPS 对外服务的完整流程。与 §2 的本地部署使用同一套 deploy/ Compose 工程，区别在于：在 Linux 服务器上构建产物与镜像、密钥改用 Linux 方式生成、外层再加一层 TLS 反向代理。

15.1 服务器规划与准备

项目建议
规格推荐 8 vCPU / 16 GiB / SSD（约 200 人并发够用）；试运行/验证环境最低 2 vCPU / 4 GiB（需调小 JVM 与 MySQL 缓存）
操作系统Ubuntu 22.04 / 24.04 LTS、Debian 12、CentOS Stream 9 等主流 64 位 Linux（内核 ≥ 5.x）

网络绑定公网 IP 或挂负载均衡；准备域名（如 oa.example.com，国内主机需完成 ICP 备案）

软件Docker Engine 24+ 与 Compose v2 插件、Git、JDK 17+、Maven 3.6+、Node.js ≥ 20.19（服务器构建时需要 JDK/Maven/Node；若仅导入镜像则不需要）
# Ubuntu/Debian 安装 Docker（官方源）

sudo usermod -aG docker $USER   # 重新登录生效

15.2 获取代码与构建产物

方式 A（在服务器上构建，适合首次实施）：

cd ..

# 4) 构建移动端 H5 静态资源（产出 agentoa-uniapp/dist/build/h5/）

# 5) 构建 Docker 镜像（在仓库根目录执行）

方式 B（本地/CI 构建镜像后上传，服务器无需 JDK/Node）：

15.3 生成密钥与配置

生产环境请在服务器上生成密钥（不要把 Windows 本机的 deploy/secrets/ 直接拷上服务器）：

cd deploy/secrets
for f in mysql-root-password db-password migration-password backup-password \
         redis-password s3-secret-key bootstrap-password; do
  [ -s "$f" ] || openssl rand -hex 24 > "$f"
done
[ -s s3-access-key ] || openssl rand -hex 10 > s3-access-key
chmod 600 *          # 仅属主可读写

再编写 S3 访问配置 deploy/secrets/s3-config（把 accessKey/secretKey 替换为上面两个文件的内容）：

{
  "identities": [
    {
      "name": "agentoa",
      "credentials": [
        { "accessKey": "<s3-access-key 文件内容>", "secretKey": "<s3-secret-key 文件内容>" }
      ],
      "actions": ["Read:agentoa", "Write:agentoa", "List:agentoa"]
    }
  ]
}

创建非敏感环境配置 deploy/.env（WebSocket 允许来源必须写对外访问的 HTTPS 域名）：

CAPTCHA_ENABLED=true
WS_ALLOWED_ORIGINS=https://oa.example.com
密钥纪律deploy/secrets/ 禁止提交到代码仓库、禁止复制进文档/聊天工具；轮换密码后需同步更新 s3-config 并重启对应服务。管理员初始密码仅存在于 bootstrap-password，首次登录改密后即作废。

15.4 端口暴露与 HTTPS 反向代理

Compose 默认把端口绑定在 127.0.0.1 上（18080 Web、18082 H5、18081 后端、13306/16379/19000 中间件），保持不变，由宿主机 Nginx（或云负载均衡）在 443 上做 TLS 终止后转发到本机 18080。

安装宿主机 Nginx 并申请证书（以 certbot 为例）：

sudo apt install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d oa.example.com     # 自动写入证书与 80 跳转

站点配置 /etc/nginx/conf.d/agentoa.conf（443 反代 + WebSocket 升级 + 上传大小与应用内 20 MiB 限制匹配）：

server {
  listen 443 ssl http2;
  server_name oa.example.com;
  ssl_certificate     /etc/letsencrypt/live/oa.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/oa.example.com/privkey.pem;

  client_max_body_size 21m;          # 应用文件上限 20 MiB，预留协议开销
  proxy_read_timeout 120s;

  location / {
    proxy_pass http://127.0.0.1:18080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
server {
  listen 80;
  server_name oa.example.com;
  return 301 https://$host$request_uri;
}
  • WebSocket 依赖 Upgrade/Connection 两行转发头，删除会导致消息推送失效。
  • 证书续期后执行 sudo nginx -t && sudo systemctl reload nginx；certbot 会自动配置定时续期。
  • 如使用云负载均衡（SLB/CLB/ALB）：监听 443 做 HTTPS 卸载，后端服务器组指向 18080，并放行 /ws 的 Upgrade（空闲超时 ≥ 120 秒）。
  • 移动端 H5（18082）建议用独立子域名（如 m.oa.example.com）在 443 反代到 127.0.0.1:18082，配置同上；H5 静态资源按根路径引用，不要挂在子路径下。
  • 防火墙：仅放行 22/80/443（sudo ufw allow 22,80,443/tcp && sudo ufw enable），数据库/缓存/存储端口不放公网。

15.5 首次启动与验收

  1. 在仓库根目录校验配置：docker compose -f deploy/compose.yml config --quiet。
  2. 启动并等待健康检查：docker compose -f deploy/compose.yml up -d --wait --wait-timeout 240。首次启动会自动执行数据库迁移（一次性 migrate 服务）并创建存储桶。
  3. 确认状态：docker compose -f deploy/compose.yml ps（全部 healthy / exited(0)）。
  4. 浏览器访问 https://oa.example.com，用 deploy/secrets/bootstrap-password 中的初始密码登录管理员账号并强制改密。
  5. 执行冒烟验证：登录、发起一条测试审批、上传/下载文件、消息中心刷新（验证 WebSocket），确认 443 与 WSS 均正常。
# 常用运维命令
docker compose -f deploy/compose.yml logs -f --tail=200 backend   # 看日志
docker compose -f deploy/compose.yml restart backend             # 重启后端
docker compose -f deploy/compose.yml down                       # 停止（保留数据卷）
docker compose -f deploy/compose.yml down -v                    # 清除数据卷（慎用，仅重装时）

15.6 升级发布

  1. 备份（见 §16.2），确认可恢复；对外公告维护窗口（可临时在 Nginx 返回维护页）。
  2. 拉取新代码/新镜像并构建（§15.2），记录镜像摘要与迁移版本。
  3. 执行 docker compose -f deploy/compose.yml up -d --build --wait：数据库迁移自动按版本顺序执行。
  4. 验证登录、待办、文件、消息后关闭维护窗口；观察错误率与 outbox 失败数。
  5. 失败回滚：切回上一版本镜像并 up -d；迁移仅前滚不回滚，如需回退结构请用备份恢复（先在隔离环境演练）。

15.7 备份上云与定时任务

备份脚本（scripts/backup-local.ps1）输出数据库 SQL、文件存储归档与 SHA256 校验清单。服务器上建议每天定时备份并异机保存（对象存储/异地机器）：

# cron 示例：每天 02:30 备份并保留 30 天（将 PowerShell 脚本迁移为 bash 或安装 pwsh）
30 2 * * *  /opt/agentoa/scripts/backup-local.sh >> /var/log/agentoa-backup.log 2>&1
# 异机同步示例（对象存储）
0 4 * * *   rclone copy /opt/agentoa/deploy/backups remote:agentoa-backups/ --min-age 1d
  • 备份成功不等于可恢复：每月至少一次在隔离环境执行恢复并记录 RPO/RTO。
  • 保留策略：本地 7 份 + 异地 30 份；备份目录权限收紧，含数据库与文件数据，等同生产数据保护级别。
  • 关键业务表也可启用 MySQL binlog，把 RPO 压缩到分钟级（需自行配置 binlog 保留）。

15.8 云环境常见问题

现象排查与解决
浏览器打不开页面安全组是否放行 80/443；curl -I https://oa.example.com；Nginx systemctl status nginx；确认 docker compose ps 中 web 为 healthy
登录后一直转圈/接口 502后端未就绪或崩溃：docker compose logs backend；首次启动迁移耗时较长，等待 migrate 退出码 0

上线门槛正式对外开放前，请对照 §16.4 检查清单逐项确认（HTTPS/WSS、密钥、日志轮转、备份恢复演练、监控告警、全量回归），阻断/严重缺陷清零后再放量。

16. 管理员运维

16.1 系统管理

  • 用户/角色/菜单/部门/岗位：标准 RBAC 维护；菜单权限串变更需与后端注解一致，勿随意删除内置菜单。
  • 字典管理：员工状态、流程状态、假种、发票类型、任务状态等字典项；业务状态语义请勿随意改动。
  • 参数/日志：系统参数、操作日志、登录日志（含 requestId，可用于问题追踪）。
  • 监控：在线用户（可强制下线）、缓存监控、数据监控。

16.2 备份与恢复

# 一致性备份（自动停止 backend/storage 写入 → 导出 MySQL + 归档文件存储 → SHA256 校验）
./scripts/backup-local.ps1        # 产物在 deploy/backups/<时间戳>/

# 恢复（在隔离环境先演练）
./scripts/restore-local.ps1
  • 备份包含：数据库 SQL、文件存储归档、SHA256 校验清单；Redis 为会话数据可不备份（恢复后需重新登录）。
  • 恢复验证标准：校验和通过、导入后表结构正确、抽样文件可下载。
  • 当前建议备份周期 ≤ 24 小时（RPO），恢复目标 ≤ 4 小时（RTO），需按实际演练记录确认。
  • 恢复应在隔离环境验证后再执行到生产；恢复后文件服务沿用原 S3 凭据。

17. 常见问题（FAQ）

问题处理办法
忘记管理员密码本地默认为 admin/123456；当前凭据见 deploy/secrets/admin-current-username / admin-current-password；或由管理员在「用户管理」中重置
登录接口返回 401「登录失败，请检查凭据或验证码」1) 核对账号密码（本地默认 admin/123456）；2) 验证码开启时须先 GET /auth/code 取 captchaCode/captchaUuid 一并提交，或在 deploy/.env 设 CAPTCHA_ENABLED=false 后重启 backend；3) 注意 /api/v1/auth/login 使用 captchaCode/captchaUuid 字段名，/auth/login 使用 code/uuid
提示「请修改初始密码」无法进入账号被标记强制改密，按提示设置 12–72 UTF-8 字节新密码；改密后需重新登录
提交申请时报 409（重复/冲突）同键重复提交会返回首次结果；若提示版本冲突/状态冲突，请刷新页面后基于最新数据重试
看不到某个菜单菜单按角色下发，请确认角色已分配并重新登录；仍缺失则联系管理员检查角色菜单授权
打开他人链接提示 404/403对象级权限拦截（私有日程、未授权知识文档等），属预期行为；需要访问请让所有者授权
请假提交提示额度不足假期按分钟账本核销，超额直接拒绝；可联系 HR 发假或查看余额台账明细
发票提示重复/超额同一发票已被占用或累计占用超面额；请核对发票列表中的占用状态，撤销原报销会自动释放
付款登记提示重复同一笔付款不允许重复登记（幂等保护）；如确需拆分付款请使用多次登记且累计不超应付金额
会议预约提示冲突时段已被占用（左闭右开，首尾相接不冲突）；请换时段或换会议室
文档编辑提示冲突他人已发布新版本，请刷新后在最新版本上继续编辑（草稿会保留）
收不到消息提醒检查右上角消息中心是否有未读（断线自动补拉）；若消息事件失败可在「投递事件」中查询并重投
页面打不开 / 接口 502执行 docker compose -f deploy/compose.yml ps 与 logs backend 排查；确认 MySQL/Redis/存储已就绪后重启 backend
上传文件失败检查文件 ≤20 MiB、扩展名/类型允许、存储服务在线；上传后下载 404 表示越权或文件不存在
移动端登录后空白确认接口地址可达（H5 自带同源反代，确认 18082 入口可达）；小程序需配置合法域名；退出后重新登录
