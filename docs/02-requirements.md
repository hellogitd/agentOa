## 1. 项目概述

### 1.1 产品定位
AgentOA 是面向中小团队的企业协同办公平台（OA），覆盖 **流程审批、组织人事、考勤打卡、报销财务、公告通知、知识库文档、日程会议任务、报表看板** 八大核心模块，帮助团队在一个平台上完成日常办公协作。

### 1.2 核心价值
- **一站式**：无需在多个系统间切换
- **流程驱动**：以审批流程为核心，将人事/财务/行政流程标准化
- **数据可见**：通过看板洞察组织人效与流程瓶颈
- **移动友好**：H5 / 小程序随时审批、打卡、查公告

### 1.3 用户角色

| 角色 | 职责 | 典型用户 |
|---|---|---|
| **超级管理员** | 系统配置、用户/角色/菜单管理；敏感业务明文需单独授权 | IT 管理员 |
| **HR 管理员** | 组织架构、员工档案、考勤规则、假期额度 | 人力资源部 |
| **部门经理** | 审批本部门流程、查看部门报表 | 各部门 Leader |
| **财务** | 报销审核、付款、对账 | 财务部 |
| **普通员工** | 发起流程、打卡、查公告、写文档、看日程 | 全员 |
| **访客（可选）** | 只读部分公开知识库 | 外包/实习生 |

### 1.4 名词解释

| 名词 | 定义 |
|---|---|
| **流程实例** | 一次具体的审批执行（如"张三的年假申请"）|
| **流程定义** | 流程模板（BPMN XML），决定节点和走向 |
| **节点** | 流程中的一个环节（发起、审批、抄送、结束）|
| **办理人** | 负责处理节点的人（具体人/角色/部门主管/发起人主管）|
| **表单** | 流程关联的数据录入页面（项目自定义、带版本的 schema）|
| **待办** | 需要当前用户处理的流程任务 |
| **考勤组** | 一群员工共享同一套考勤规则 |

### 1.5 建议交付基线与范围边界

本次优化保留八大模块目标，建议按以下范围分阶段交付。P0 是 v1.0 必须验收的最小能力，P1/P2 是后续待办；详细需求中的扩展能力不自动进入 P0。以下为待产品评审的建议基线，不代表范围已获业务方确认。

| 阶段 | P0 交付 | 后续扩展 |
|---|---|---|
| M0 | 单组织、账号/RBAC、私有附件、审计、迁移、部署 | 多租户、SSO、K8s |
| M1 | 部门/岗位、基础档案、入职/转正/离职；固定流程模板、表单渲染、版本、同意/拒绝/转办/撤销、待办和历史 | 拖拽设计器、会签/或签、任意退回、加签、代理、挂起 |
| M2 | 固定班、PC/H5 基础打卡、请假额度、加班/补卡、报销与发票去重、一次全额付款登记、公告和站内信 | 轮班、外勤拍照、预算、OCR、真实支付渠道 |
| M3 | 空间成员权限、Markdown 文档与版本、文件柜、搜索；单次日程、会议室冲突检测、基础任务 | 文件夹覆盖权限、富文本双编辑器、重复日程、扫码签到、看板和任务依赖 |
| M4 | 工作台、四类基础看板、人工导出、H5 审批/打卡/公告；正式验收 | 多小程序、定时报表、外部协同集成 |

首版六个流程模板为请假、加班、补卡、报销、转正、离职。M1 先验证引擎与人事模板；涉及考勤/财务账本的业务在 M2 验收。其余六个模板保留为 P1。M2 完成后可内部试点，M4 完成 P0 后才是 v1.0。

首版仅单组织、人民币报销与人工付款登记，不包含工资计算、记账总账、银行付款、法定合规认证或强防作弊考勤。计划为 20 个工作周，估算条件见 [路线图](07-roadmap.md)。

### 2.1 功能清单

| # | 功能 | 优先级 | 说明 |
|---|---|---|---|
| HR-01 | 部门管理 | P0 | 多级部门树、增删改、启停用 |
| HR-02 | 岗位管理 | P0 | 岗位名称、职级、职等、部门挂载 |
| HR-03 | 员工档案 | P0 | 基础身份与组织信息；教育/工作经历、合同、证照扩展为 P1 |
| HR-04 | 入职办理 | P0 | 新员工录入、账号开通、岗位分配 |
| HR-05 | 转正 | P0 | 试用期到期提醒、转正流程 |
| HR-06 | 调岗调薪 | P1 | 部门/岗位/薪资异动，历史可追溯 |
| HR-07 | 离职办理 | P0 | 离职流程、账号冻结、工作交接 |
| HR-08 | 花名册 | P0 | 全员列表、多维筛选、Excel 导入导出 |
| HR-09 | 合同管理 | P1 | 合同起止、续签提醒 |
| HR-10 | 员工自助 | P1 | 个人信息维护、查看假期余额 |

### 2.2 详细需求

#### HR-01 部门管理
- **数据字段**：部门名称、上级部门、部门编码、负责人、排序、状态（启用/停用）、备注
- **业务规则**：
  - 支持无限层级（建议 ≤ 5 级）
  - 删除部门需无关联员工
  - 停用部门后其下员工需先调整
- **操作**：新增、编辑、删除、启停用、拖拽排序

#### HR-02 岗位管理
- **数据字段**：岗位名称、岗位编码、职级（如 P6/M2）、职等、所属部门、岗位职责、状态
- **业务规则**：
  - 岗位挂在部门下，部门删除时岗位需先处理
  - 职级用于审批流（如"P7 以上需总监审批"）

#### HR-03 员工档案
- **基本信息**：姓名、工号、性别、出生日期、手机号、邮箱、身份证号（加密存储）、住址、紧急联系人
- **组织信息**：部门、岗位、职级、直属上级、入职日期、员工类型（正式/实习/外包）
- **教育经历**：学校、专业、学历、学位、起止时间
- **工作经历**：公司、职位、起止时间、离职原因
- **合同信息**：合同类型、起止日期、合同期限
- **证照信息**：证照类型、编号、有效期
- **业务规则**：
  - 手机号、身份证号唯一性校验
  - 敏感字段（身份证、手机号）需加密存储（AES-256）
  - 工号自动生成规则可配置（如 `AY20260001`）

#### HR-04 入职办理
- **流程**：
  1. HR 录入基本信息 → 系统生成工号
  2. 自动开通待激活账号，通过受控流程设置首次密码
  3. 发送入职站内通知；邮件通知为 P2
  4. 分配部门、岗位、直属上级
- **字段**：入职日期、员工类型、试用期（默认 3 个月）、转正日期（自动算）

#### HR-05 转正
- **触发**：转正日期前 7 天自动提醒 HR + 员工
- **流程**：员工发起转正申请 → 主管评价 → HR 复核 → 更新状态为"正式"
- **字段**：转正日期、试用期评价、转正薪资

#### HR-06 调岗调薪
- **流程**：发起 → 原主管 → 新主管 → HR → 财务（若调薪）
- **字段**：异动类型（调岗/调薪/晋升/降级）、生效日期、原部门/岗位、新部门/岗位、原薪资、新薪资
- **规则**：
  - 异动记录入"员工异动历史"表
  - 调岗后即时生效还是次月生效可选

#### HR-07 离职办理
- **流程**：员工发起 → 主管审批 → HR 面谈 → 各部门交接（IT 归还设备、财务结算、行政归还钥匙）→ HR 完成 → 账号冻结
- **字段**：离职日期、离职原因（个人/公司/合同到期）、交接人、交接清单
- **规则**：
  - 离职后账号不能登录但历史记录保留
  - 按档案、合同、财务、审计等数据类别确定留存期；到期经审批删除或匿名化，法务冻结期间禁止清除，不以固定三年删除宣称合规

#### HR-08 花名册
- **筛选维度**：部门、岗位、职级、员工状态、入职日期、转正状态
- **导出**：Excel（含全部可见字段）
- **批量操作**：批量调岗、批量停用、批量导出

### 3.2 流程引擎需求

**基于 Flowable BPMN 2.0 的目标能力**。P0 仅发起、串行用户任务、受控服务任务、排他网关、结束节点；其余节点为 P1，以下为完整规划：

| 节点类型 | 说明 | 配置项 |
|---|---|---|
| **发起节点** | 流程起点 | 发起人范围（全员/指定部门/指定角色）|
| **用户任务** | 人工审批 | 办理人规则、会签/或签、超时、表单权限 |
| **服务任务** | 自动任务 | 触发通知、更新状态、调用外部接口 |
| **排他网关** | 二选一分支 | 条件表达式 |
| **并行网关** | 并行分支 | 并行节点数 |
| **包容网关** | 条件并行 | 动态并行数 |
| **子流程** | 嵌套流程 | 复用通用环节 |
| **抄送节点** | 知会 | 抄送人列表 |
| **结束节点** | 流程终点 | 结束状态（通过/拒绝）|

**办理人规则**：
- 指定成员（具体用户）
- 指定角色（角色下所有用户）
- 指定部门（部门主管/部门所有人）
- 发起人自选
- 发起人主管（N 级主管）
- 发起人自己（自审批）
- 表单变量（如表单里的"项目经理"字段）

**分支条件表达式**（示意；P0 使用白名单字段/运算符生成引擎条件，禁止任意 SpEL、Bean 调用和用户脚本）：
```javascript
// 示例：金额 > 5000 走总监审批
${amount > 5000}
// 示例：部门 = 技术部
${deptCode == 'TECH'}
// 示例：复合条件
${amount > 5000 && deptCode == 'TECH'}
```

| 类型 | 说明 | 校验 |
|---|---|---|
| 单行文本 | 普通文本 | 长度、正则、必填 |
| 多行文本 | 富文本/纯文本 | 长度 |
| 数字 | 整数/小数 | 范围、精度 |
| 单选/多选 | 枚举选项 | 必填 |
| 下拉选择 | 枚举/数据源 | 必填 |
| 日期 | 年月日 | 范围 |
| 日期时间 | 年月日时分 | 范围 |
| 时间段 | 起止日期 | 时长计算 |
| 级联 | 省市区/多级部门 | 层级 |
| 人员选择 | 单人/多人 | 范围限制 |
| 部门选择 | 单部门/多部门 | - |
| 附件 | 单文件/多文件 | 大小、类型 |
| 图片 | 单图/多图 | 大小、类型 |
| 金额 | 带千分位 | 范围 |

| 流程 | 表单字段 | 节点 |

| **名片/工牌申请** | 数量、用途 | 行政 |
| **调岗调薪** | 异动类型、新岗位、新薪资 | 原主管 → 新主管 → HR → 财务 |

### 3.5 审批操作

| 操作 | 说明 | 影响 |
|---|---|---|
| **同意** | 通过当前节点 | 流程走向下一节点 |
| **拒绝** | 拒绝整个流程 | 流程终止，状态为"拒绝" |
| **退回** | 退回到发起人/历史节点 | 可修改后重新提交 |
| **转办** | 把任务转给他人 | 新办理人处理 |
| **加签** | 增加临时办理人 | 前加签/后加签 |
| **挂起** | 暂停流程 | 需要时可恢复 |
| **催办** | 发起人催办 | 站内信/短信提醒 |
| **撤销** | 发起人在审批中且无人完成审批时撤回 | 原实例保留，释放额度/发票占用 |

## 4. 模块三：考勤打卡（Attendance）

### 4.1 功能清单

| # | 功能 | 优先级 | 说明 |
|---|---|---|---|
| AT-01 | 考勤组管理 | P0 | 分组、绑定员工、绑定班次 |
| AT-02 | 班次管理 | P0 | 上下班时间、弹性、休息、打卡窗口 |
| AT-03 | 排班管理 | P1 | 固定/轮班/自定义排班 |
| AT-04 | 打卡记录 | P0 | PC/H5 基础定位或经确认的 IP 规则；WiFi 校验、外勤为 P1 |
| AT-05 | 考勤规则 | P0 | 迟到/早退/旷工判定、豁免规则 |
| AT-06 | 请假额度 | P0 | 年假/调休/病/事假，按 HR 确认的政策计算 |
| AT-07 | 加班管理 | P0 | 加班申请、加班时长统计 |
| AT-08 | 补卡 | P0 | 忘打卡补卡、限定次数 |
| AT-09 | 外勤打卡 | P1 | GPS 定位 + 现场照片 |
| AT-10 | 考勤统计 | P0 | 月度报表、异常提醒 |
| AT-11 | 考勤申诉 | P2 | 员工对异常提出申诉 |

### 4.2 详细需求

#### AT-02 班次管理
- **字段**：班次名称、上班时间、下班时间、是否弹性、弹性时间窗、休息时段、跨夜班
- **示例**：
  - 固定班：09:00 - 18:00（午休 12:00-13:00）
  - 弹性班：09:00±30min - 18:00±30min（工作 8h）
  - 跨夜班：22:00 - 次日 06:00

#### AT-04 打卡记录
- **字段**：用户、打卡时间、打卡类型（上班/下班/外勤）、定位（GPS 经纬度+详细地址）、设备（Web/App）、IP、WiFi 名、现场照片（外勤）
- **规则**：
  - 记录窗口与迟到/早退阈值分别配置；窗口内迟到仍应记录，不能因超过 15 分钟直接丢失迟到事实
  - 外勤打卡必须有 GPS 定位 + 照片
  - 补卡需走补卡流程
  - 保留全部原始记录，按班次窗口计算首次/末次有效打卡；跨夜班归属开始日，时间以服务器接收值为准

#### AT-05 考勤规则
- **判定规则**：
  - 迟到：有效上班打卡晚于班次开始加宽限时间
  - 早退：有效下班打卡早于班次结束减宽限时间
  - 旷工：当日无打卡且无请假
  - 豁免：如哺乳期、外派人员不计迟到
- **容错**：允许每月 N 次迟到豁免

#### AT-06 请假额度
- **额度类型**：年假、调休、病假、事假、婚假、产假、陪产假、丧假
- **计算规则**：
  - 年假：按适用地区、累计工龄及组织政策配置，由 HR 确认；不能把司龄示例当作法定年假标准
  - 调休：按 HR 确认的加班折算比例累积；P0 按年度统一到期，按批次滚动 3 个月等有效期规则为 P1
  - 病假/事假：不计额度但需审批
- **额度账本**：统一整数分钟；提交冻结、通过转已用、拒绝/撤销释放；并发申请不得透支，事件重复执行不得重复扣减
- **时长**：服务端依据工作日历、班次和休息时段计算；跨日、半天、跨年和节假日场景必须验收
- **查询**：员工可查余额

#### AT-10 考勤统计
- **日报**：当日打卡明细、异常名单
- **月报**：每人出勤天数、迟到/早退/旷工次数、加班时长、请假天数
- **导出**：Excel（供薪资核算）
- **异常提醒**：下班忘打卡、连续多日异常，站内信/企业微信提醒

### 5.2 详细需求

#### FN-02 报销单
- **主字段**：报销单号、申请人、申请日期、报销类型、报销总额、币种、支付方式
- **明细字段**：费用类型、发生日期、金额、发票号、发票图片、说明
- **流程联动**：
  - 金额 ≤ 1000 元：主管 → 财务
  - 1000 < 金额 ≤ 5000 元：主管 → 财务 → 出纳
  - 金额 > 5000 元：主管 → 财务 → 总监 → 出纳
- **规则**：
  - 明细总额必须等于主表总额
  - 按发票类型、代码（无代码用空串）与号码规范化去重；同一发票不得被多个在途/已付款报销占用
  - 报销需附发票图片（可选 OCR 识别）
  - 拒绝/撤销后可修改重提，新提交创建新流程实例并保留历史；金额由服务器汇总，API 使用两位小数字符串
  - 全额付款登记仅允许已通过且未付款的报销，由出纳权限执行；重试不得生成第二笔付款，不支持直接修改付款状态绕过校验

#### FN-03 预算管理
- **维度**：部门年度预算 + 项目预算
- **字段**：预算期（年度/季度/月度）、总金额、已用金额、剩余额度、预警阈值（如 80%）
- **规则**：
  - 报销提交时校验剩余额度，超支需走特殊审批
  - 预算调整走独立流程

#### FN-04 发票管理
- **字段**：发票号、代码、金额、税额、开票日期、购买方、销售方、发票图片、OCR 识别结果
- **能力**：
  - 上传发票图片，OCR 识别（可选集成百度/腾讯 OCR）
  - 发票号唯一性校验（防重复报销）
  - 发票真伪验证（可选对接税务 API）

#### FN-05 付款管理
- **字段**：付款单号、关联报销单、收款人、开户行、账号、付款金额、付款日期、付款状态（待付/已付/失败）
- **流程**：财务审核 → 出纳付款 → 标记完成

#### AI-04 AI 对话助手
- **会话**：本人可见，创建/列表/重命名/删除（软删），首条消息自动命名
- **消息与记忆**：上下文按模型窗口截断；持久化消息即记忆来源
- **流式**：SSE 逐 token 推送（delta/done/error/usage 事件），支持停止生成与重新生成（保留旧版本）
- **失败处理**：限额超限、能力不匹配、超时分别给出可读提示

#### AI-05 多模态输入
- 图片 ≤5 张、单张 ≤10 MiB（jpg/png/webp），复用 `sys_file` + 私有 S3 + 扩展名/魔数/MIME 三重校验；vision 模型以 image content 参与推理，非 vision 模型 400 拒绝

#### AI-08 业务 Copilot
- **只出建议，不落业务库**：输出为草稿/建议值，人工确认后才生效；AI 不直接修改业务数据
- 每场景独立开关与模型/模板配置；长文生成走异步任务（`oa_ai_copilot_task`），完成经 outbox/WS 通知
- 输入数据最小化：仅取场景所需字段，不取无关敏感字段

#### AI-09 Agent 与 MCP
- 工具执行带调用者身份，**照常走对象权限**；写操作工具需 `ai:tool:write` + 人工确认；步数/超时熔断
- 外部 MCP server 登记与工具发现；Agent 配置（模型、工具集、最大步数）；执行轨迹可审计回放

### 11.3 非功能与验收基线

- 流式首 token P95 ≤ 3s（上游正常）；AI 故障不影响 OA 主流程；限额/日志异步不阻塞对话
- 对话与知识内容按用户/授权服务端过滤，无权限即 404；AI 生成内容 UI 明示"仅供参考"
- 各阶段验收口径：M1 配 Key→测试连接→限额与日志闭环；M2 真实多轮对话+传图识别；M3 引用可跳转不越权；M4 业务数据零污染；M5 跨工具任务+轨迹回放

## 12. 非功能性需求

### 12.1 性能需求

以下为待压测目标：参考环境 8 vCPU/16 GiB、SSD，数据库 200 名员工、10 万流程实例、100 万打卡记录；200 个并发虚拟用户，查询/审批/打卡按 70%/20%/10% 混合，思考时间 3–5 秒，预热 5 分钟、持续 30 分钟。记录吞吐量、p95、错误率与资源占用，不把“200 在线”当作“200 QPS”。文件传输与导出单独评测。

| 指标 | 目标 |
|---|---|
| 登录响应时间 | 服务端 p95 < 1s |
| 列表查询（每页最多 100 条）| 服务端 p95 < 500ms |
| 流程提交 | 服务端 p95 < 2s |
| 并发用户 | ≥ 200 |
| 核心请求错误率 | < 1%，不含预期的校验/并发冲突；不得出现账本不一致 |
| WebSocket 在线连接 | ≥ 500 |

### 12.2 安全需求
- **认证**：Sa-Token 不透明 Bearer 会话令牌 + Redis；绝对有效期 2h、空闲 30min，过期重新登录；SSO 为后续能力
- **权限**：RBAC + 按钮级 + 数据权限（本人/本部门/全部）
- **数据加密**：
  - 敏感字段 AES-256-GCM（身份证、银行卡、手机号、薪资）；精确匹配用 HMAC 索引，密钥单独管理
  - 密码 BCrypt
  - 传输层 HTTPS
- **审计**：登录日志、操作日志（AOP + 注解）
- **XSS/CSRF**：输出转义、富文本允许列表；Bearer 不由浏览器自动附带，若改 Cookie 认证须另行实施 CSRF Token 与 SameSite
- **接口防护**：限流（Sentinel/RateLimiter）、参数校验（Hibernate Validator）
- **文件安全**：上传白名单、病毒扫描（可选）

### 12.3 可用性需求
- **可用性**：≥ 99.5%（每月停机 < 3.6 小时）
- **备份**：数据库与附件每日一致性备份并复制到异机；试点 RPO ≤ 24h、RTO ≤ 4h，必须实测
- **容灾**：备份不是高可用；更短 RPO 需另行验证 binlog 归档和时间点恢复
- **监控**：Spring Boot Actuator + Prometheus + Grafana
- **告警**：异常自动邮件/钉钉通知

### 12.4 兼容性需求
- **浏览器**：发布时 Chrome/Edge/Firefox 最近两个稳定主版本、Safari 当前及上一主版本；M0 锁定验证清单（不支持 IE）
- **移动**：H5 真机覆盖团队实际使用的 iOS/Android 版本；定位/相机授权、拒绝授权、断网重试均需验收
- **屏幕**：1280×720 至 3840×2160 自适应

### 12.5 可扩展性
- 模块化设计，新增业务模块不影响核心
- 数据库分表预留（流程实例、日志表）
- 支持水平扩展（多实例 + Redis Session）
- API 版本化（`/api/v1/...`）

## 14. 附录

### 14.1 优先级定义
- **P0**：核心功能，必须在 MVP 中交付
- **P1**：后续重要能力，另行排期，不承诺 MVP 后固定月数内交付
- **P2**：增值功能，按需开发

### 14.2 状态定义
- **流程状态**：1 审批中 → 2 已通过 / 3 已拒绝 / 4 已撤销 / 6 已终止；5 已挂起为 P1 且可恢复为 1。超时是独立标志。草稿在业务单据中，不创建引擎实例
- **员工状态**：待入职 → 试用期 → 正式 → 离职中 → 已离职
- **报销状态**：1 草稿 → 2 审批中 → 3 已通过 → 5 待付款 → 6 已付款；2 也可 → 4 已拒绝 / 7 已撤销，4/7 修改后回到 1 重提。管理员终止审批时业务归为 7 并保留终止原因；付款登记可从 3/5 进入 6

### 14.3 关键验收场景

| 需求 | 验收场景 | 预期结果 |
|---|---|---|
| HR-07 | 离职账号仍持有旧令牌 | 登录与已有会话均失效，历史审计可查 |
| WF-04/06 | 发布新模板；两次并发完成同一任务 | 旧实例版本不变；只执行一次审批，冲突返回 409 |
| AT-06 | 两个申请同时冻结同一余额；拒绝与重试 | 不透支；只释放一次，流水可对账 |
| FN-02/04/05 | 重复发票、总额篡改、重复付款 | 冲突被拒；金额服务端计算；同一次付款只登记一次 |
| NC-02/06 | 提交后断开 WebSocket，稍后重连 | 站内信仍存在，补拉不丢失、不重复 |
| KB-08 | 非成员通过详情/搜索/下载/历史访问私密空间 | 全部拒绝且不泄露标题、片段和附件 |
| CL-04 | 两人同时预约同一会议室重叠时段 | 仅一个成功，另一个返回 409；相邻时段允许 |
| RP-07 | 员工导出其他部门数据 | 无法越权；统计与导出使用同一权限和筛选口径 |
| 运维 | 用备份在隔离环境恢复数据库与附件 | 能登录、查看审批与下载附件，达到 RPO/RTO |

### 14.4 报表口径

时间区间统一采用组织时区的左闭右开区间。审批平均时长取区间内已结束实例的结束时间减开始时间，排除仍在途实例并单列拒绝/撤销；人数按员工状态与生效日期统计。出勤率为实际出勤分钟/应出勤分钟，应出勤扣除已批准请假和非工作时间，分母为零返回 null。财务申请额按提交时间、批准额按批准时间、实付额按付款时间分别统计，不混为一个“报销总额”；预算指标待 P1 启用。
