# 模块 9：发布、移动端与最终验收计划

## 目标与边界

把已完成的 P0 模块交付为可回归、可恢复的 v1.0。包括 H5 审批/打卡/公告入口、生产 HTTPS/WSS、容量测试、备份恢复、监控告警、用户手册和培训；小程序、SSO、外部消息、复杂 BI 不纳入本次发布。

## 顺序

1. 冻结 API、迁移、镜像和配置版本，生成发布清单和回滚点。
2. 做全量回归：认证、HR、六个流程、考勤、报销、公告、知识、协同、报表。
3. 做安全回归：越权、敏感字段、文件下载、日志脱敏、验证码、会话失效和请求追踪。
4. 做容量测试：登录、列表、打卡、待办、上传、报表和 WebSocket 连接，记录基线、瓶颈和资源曲线。
5. 在隔离环境执行数据库/文件恢复，测量 RPO/RTO；演练迁移失败、后端回滚和消息重投。
6. 完成 H5 真机测试、浏览器兼容、无障碍关键路径、用户手册和管理员运维手册。
7. 试点发布，收集阻断/严重缺陷，确认业务负责人、运维负责人和回滚负责人签字。

## 测试与发布门槛

- 所有 P0 验收用例通过，阻断/严重缺陷为零。
- 迁移可从空库和上一版本升级；版本、镜像摘要和配置可追溯。
- 备份可恢复，RPO ≤ 24 小时、RTO ≤ 4 小时的目标有实测记录；达不到必须延期或调整目标。
- HTTPS/WSS、密钥管理、日志轮转、告警、最小权限账号和异机备份已配置。
- H5 审批、打卡、公告在目标设备上通过；用户知道刷新会话、密码和文件权限规则。（H5 端 H1–H6 功能已交付，[23](23-module-plan-h5.md) §7；真机验收执行清单与签署见 [24](24-release-acceptance-checklist.md)。）
- 浏览器兼容矩阵、无障碍人工验收与消息时延记录按 [24](24-release-acceptance-checklist.md) 清单执行并签署（自动化基线由 `browser-smoke.mjs` 产出 axe 报告与时延记录）。

退出条件是全量回归、安全回归、容量测试、恢复演练和 H5 真机验收均有记录，阻断/严重缺陷清零，业务、运维和回滚负责人共同签字后才发布 v1.0。

发布后保留回滚版本和迁移说明，观察期内每天核对错误率、待办延迟、outbox 失败、存储容量和数据库备份。v1.0 完成后，P1 需求另立范围和估算，不在维护窗口直接插入。
